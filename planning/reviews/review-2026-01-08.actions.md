**Full-component dragging: FIXED ✅**

The root cause was a coordinate system mismatch between PixiJS container-local coordinates and canvas-relative coordinates:
- PixiJS containers are offset by 20px (X) and 25px (Y) for label padding
- `positionToPixels()` returns container-local coordinates (without padding offset)
- Mouse events provide canvas-relative coordinates (including padding offset)
- This 20px/25px mismatch caused components to snap to incorrect grid positions during dragging

**Fixed in `breadboard-app.ts`:**

1. **`snapToGrid()` method (lines 2025-2038):**

   - Ensures correct grid position calculation

   ```typescript
   // Before: Ignored padding offset
   const col = Math.round(pixels.x / HOLE_SPACING);
   
   // After: Account for label padding
   const gridX = pixels.x - PixiRenderer.LABEL_PADDING_X;
   const gridY = pixels.y - PixiRenderer.LABEL_PADDING_Y;
   const col = Math.round(gridX / PixiRenderer.HOLE_SPACING);
   ```

2. **`handleComponentDragStart()` method (lines 1604-1647):**
   - Now adds label padding to pin coordinates when calculating drag offset
   - Synchronizes coordinate systems between container and canvas space

   ```typescript
   // Before: Mixed coordinate systems

   const offsetY = firstPinCanvasY - mouseY;
   ```

**Fixed in `pixi-renderer.ts`:**

### Technical Implementation Summary

**Problem Root Cause:**

PixiJS uses a layered container architecture where the breadboard, components, and overlays are positioned inside containers that have a 20×25px offset (for label padding). This creates two coordinate spaces:

1. **Container-local space:** Returned by `positionToPixels()`, origin at (0,0) of the container
2. **Canvas-relative space:** Used by mouse events, origin at (0,0) of the entire canvas (includes padding)

The drag-and-drop logic was mixing these coordinate spaces, causing:
- Horizontal dragging to fail completely (20px offset accumulated in X direction)
- Vertical dragging to be unreliable (25px offset accumulated in Y direction)
- Components snapping to wrong grid positions (offset by 1-2 holes)

**Solution Architecture:**

The fix maintains coordinate space consistency by:
1. When converting canvas coordinates → grid positions: **subtract padding first**
2. When converting container coordinates → canvas coordinates: **add padding**
3. Expose padding constants as `public static readonly` to ensure single source of truth

- ❌ "This appears to be a bug rather than a design decision"

The root cause was that component containers used full bounding-box hit detection, which blocked clicks on adjacent breadboard holes. For 2-pin components (resistors, LEDs), the bounding box includes empty space between pins where holes exist but were unclickable.

**Fixed in `pixi-renderer.ts`:**

   ```typescript
   // Before: entire bounding box was interactive, blocking holes
   container.eventMode = 'static';
   container.cursor = 'pointer';
   
   // After: only actual component visual is interactive
   const hitArea = this.createComponentHitArea(component);
   if (hitArea) {
     container.hitArea = hitArea; // Custom geometry per component type
   }
   ```

2. **Per-component-type hit detection (lines 1011-1143 - new method):**
   - **Wires:** Manhattan path segments only (8px tolerance)
     - Checks vertical-horizontal-vertical routing path
     - Does not block holes outside the wire path
   - **Resistors/LEDs:** Body + lead connection points, not space between pins
     - Resistor: 60×20px rectangular body + lead endpoints
     - LED: 15px circular body + lead endpoints
     - Empty space between pins is NOT part of hit area
   - **Power/Ground symbols:** Symbol bounds only (20×30px / 30×20px)
   - **Microprocessor:** Chip body bounds only (80×120px)

3. **Improved hole hit areas (lines 614-629):**

   - Hit area is larger than visual hole for easier clicking

4. **Component dimensions extracted as constants (lines 87-96):**
   - `RESISTOR_BODY_WIDTH = 60`, `RESISTOR_BODY_HEIGHT = 20`
   - `LED_BODY_RADIUS = 15`
   - `POWER_SUPPLY_SYMBOL_HEIGHT = 30`, `POWER_SUPPLY_SYMBOL_WIDTH = 20`
   - `GROUND_SYMBOL_WIDTH = 30`, `GROUND_SYMBOL_HEIGHT = 20`
   - `MICROPROCESSOR_WIDTH = 80`, `MICROPROCESSOR_HEIGHT = 120`
   - Ensures hit areas match rendered dimensions exactly

**4. Undo/Redo Support (NEW) ✅**

**Command Implementation in `src/core/command.ts`:**

```typescript
export class RepositionPinCommand implements Command {
  readonly description: string;

  constructor(
    private componentId: string,
    private pinIndex: number,
    private oldPosition: Position,
    private newPosition: Position
  ) {
    this.description = `Reposition pin ${pinIndex}`;
  }

  execute(state: BreadboardState): BreadboardState {
    return {
      ...state,
      components: state.components.map((c) => {
        if (c.id === this.componentId) {
          const newPositions = [...c.positions];
          newPositions[this.pinIndex] = this.newPosition;
          return { ...c, positions: newPositions };
        }
        return c;
      }),
    };
  }

  undo(state: BreadboardState): BreadboardState {
```

```typescript
private isComponentBent(positions: Position[]): boolean {
  if (positions.length !== 2) return false;
  
  const rowDiff = Math.abs(positions[1].row - positions[0].row);
```
