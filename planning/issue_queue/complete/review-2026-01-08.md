# Breadboard Application Review – Structured Feedback

This document captures all review feedback from hands-on use of the application. No points have been omitted; the content has been reorganised for clarity, prioritisation, and direct usability as design or development notes.

---

## 1. Overall Layout & Information Architecture

### 1.1 Left vs Right Sidebar Balance

- The **left-hand sidebar is overloaded**, while the **right-hand sidebar is underutilised**.
- There is significant unused space on the right that could be repurposed more effectively.

### 1.2 Proposed High-Level Layout Rebalancing

**Left Sidebar**

- Component Library (top, unchanged)
- Quick Select (below Component Library)
- Examples
- Load Circuit
- Save Circuit
- Clear All (conceptually belongs with component manipulation)

**Right Sidebar**

- View controls
- Audio Output
- Clock Control
- Component Properties (retain)
- Remove all other panels that provide no clear user value

---

## 2. Quick Select Panel

### 2.1 Visual Design Issues

- Icons do **not use the full width** of the sidebar.
- Icons are **too square** and visually cramped.
- Labels are **hard to read**.
- Unclear text such as `322S5` appears, with no obvious meaning to users.
- The panel feels visually secondary despite being a primary interaction surface.

### 2.2 Expected Design & Behaviour

- Quick Select should use **clear, recognisable component icons** (e.g. resistor, LED, diode).
- The **Component Library already contains category icons** (diodes, LEDs, power supplies, etc.):
  - These should be reused for visual consistency.
- Quick Select items should:
  - Use more horizontal width
  - Use more intelligent vertical spacing
- The panel should feel like a **fast-access component palette**, not a compressed list.

### 2.3 Functional Gaps

- There is **no way to remove items** from Quick Select.
- Clicking a Quick Select item currently **does nothing**.
- Expected behaviour:
  - Clicking an item spawns a new component off the breadboard, ready to be placed.

---

## 3. Examples, Load/Save, and Clear Controls

### 3.1 Examples

- The example circuits are “quite nice”.
- It is acceptable that these will change later.

### 3.2 Control Placement

- Consider moving **Examples / Load Circuit / Save Circuit** to the right sidebar.
- **Clear All** feels semantically tied to component editing and should likely remain on the left with components.

---

## 4. Right Sidebar: Circuit Info & Lists

### 4.1 Circuit Info / Nodes / Connections

- These sections provide **no clear value** in their current form.
- Their purpose is unclear to users.
- Recommendation: **remove entirely**.

### 4.2 Component List

- The component list provides little value because:
  - Components are already visible on the breadboard.
  - Multiple wires are indistinguishable in a list.
  - The same problem applies to resistors and other repeated components.
- Selecting wires or resistors from a list is not meaningful if they cannot be visually differentiated.

### 4.3 Component Properties (Keep)

- Component Properties is **very useful**.
- Clicking a component and immediately editing its properties is a strong UX feature.
- This panel should be retained and expanded.

### 4.4 Selection Feedback Gap

- When a wire is selected:
  - Nothing appears in Component Properties.
  - There is no clear indication that the wire is selected.
- Even if wires have limited editable properties:
  - Selection state must still be visible.
  - Component Properties could later support wire-specific editing.

---

## 5. Component Interaction & Manipulation

### 5.1 Drag-and-Drop Issues

- Dragging components is unreliable or broken.
- Horizontal dragging does not work correctly.
- It is not possible to:
  - Drag a component freely
  - Drag an individual leg independently
- The interaction feels frustrating and inconsistent.

### 5.2 Expected Interaction Model

- Users should be able to:
  - Drag an entire component as a unit
  - Select and move individual legs independently
- This is essential for realistic breadboard usage.

### 5.3 Breadboard Slot Selection Bug

- Users should be able to select **any breadboard hole or slot** directly.
- This does not appear to work reliably.
- This appears to be a bug rather than a design decision.

---

## 6. Rotation & Orientation

### 6.1 Component Rotation

- There is **no obvious way to rotate components**.
- Rotation is essential for realistic placement.

### 6.2 Breadboard Orientation

- The breadboard is currently oriented vertically (portrait).
- This is unusual; most breadboards are shown horizontally (landscape).
- Proposed solution:
  - Add a button in the main pane to rotate the entire breadboard
  - Support rotation in 90° increments (90 / 180 / 270 / 360)

---

## 7. Rendering & Technology Concerns

- The application is intended to use **React + Konva**.
- Visually, it still appears to behave like **PixiJS**.
- This needs confirmation:
  - Either the migration is incomplete
  - Or the visual output does not yet reflect the new rendering stack

---

## 8. X-Ray Mode

### 8.1 Current Behaviour

- X-ray mode changes the background to grey.
- It does **not clearly reveal breadboard rails**.
- The intent of the mode is therefore unclear.

### 8.2 Intended Purpose

X-ray mode should:

- Reveal **hidden internal breadboard connections**
- Show:
  - Horizontal row connections
  - Vertical rail connections
- Explain what cannot normally be seen physically

### 8.3 Visual Recommendations

- When X-ray is enabled:
  - Components and wires should become **monochromatic**
  - Components should be **partially transparent**
  - Breadboard internal wiring should be visually emphasised
- The mode should feel educational, not cosmetic.

---

## 9. Breadboard Visual Realism

### 9.1 Colouring

- Red and blue rails do **not look realistic**.
- Most real breadboards are white or neutral.
- Power rails are not inherently positive or negative:
  - Polarity depends on how the user connects power.
- Recommendation:
  - Remove red/blue colouring
  - Use subtle, realistic tones
  - Let polarity be inferred from connections, not colour

### 9.2 Hole Geometry

- Breadboard holes are visually **too large**.
- Real breadboard holes are much smaller.

### 9.3 Desired Compromise

- **Visual hole**: small and realistic
- **Selection hit area**: large and forgiving
- This preserves usability without sacrificing realism.

---

## 10. Dark / Light Theme

- A dark/light theme toggle should be placed in the **top-right corner**.
- Use the existing React Light/Dark toggle component from your own NPM package.

---

## 11. Critical Functional Blocker

> The most serious issue is that **core interaction does not currently work**.

Specifically:

- Clicking Quick Select does nothing
- Components cannot be reliably dragged
- Legs cannot be repositioned
- Breadboard holes cannot always be selected

Until these issues are resolved, meaningful editing is not possible.

---

## 12. Priority Summary

### Blocking Issues

- Drag-and-drop failures
- Quick Select click produces no component
- Unreliable breadboard hole selection

### High Priority UX Improvements

- Quick Select redesign
- Sidebar rebalancing
- Component and board rotation
- X-ray mode clarity

### Medium Priority Improvements

- Breadboard visual realism
- Hole sizing vs hit area
- Dark/light theme toggle
